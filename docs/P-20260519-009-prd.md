# PRD: cultivation-simulator DDD 重构

## 1. 背景与目标

### 背景
- `game.js` 当前 17,717 行，单体文件，所有逻辑混合
- UI 层（DOM操作）和领域逻辑交错，缺乏边界
- 每次迭代出问题，根因是构建零验证 + 代码耦合
- 已完成：构建系统重构（build_vite.js + CI验证）

### 目标
**Freeze 功能，重构成干净 DDD 架构，再迭代。**

## 2. 限界上下文识别

初步拆分 7 个 Bounded Contexts：

| Context | 核心概念 | 关键实体/聚合 |
|---------|---------|--------------|
| **Cultivation** | 修炼、突破、天劫 | Player, Realm, Tribulation |
| **Pet** | 灵兽、融合、变异、觉醒 | Pet, Gene, AwakeningSkill |
| **Combat** | 回合制战斗、PVP | CombatState, Action, Turn |
| **Ranking** | 天梯、段位、排行榜 | RankInfo, Season, Opponent |
| **Achievement** | 成就、称号、季节奖励 | Achievement, Title, SeasonReward |
| **Inventory** | 物品、装备、灵石、消耗品 | Item, Equipment, Treasure |
| **UI** | 渲染层、弹窗、DOM 操作 | View层，调用各Context服务 |

## 3. 重构原则

1. **增量拆分，不重写**：保持功能不变，逐步从 game.js 提取模块
2. **单向依赖**：UI → DomainService → Entity/Aggregate → ValueObject
3. **显式接口**：跨 Context 调用通过 DomainService 暴露，不直接访问其他域的内部状态
4. **保留全局 state**：gameState 作为只读快照，各模块读取而非直接修改
5. **ESM 模块化**：每个 Context 一个 .js 文件，`export` 关键函数
6. **node --check 可验证**：每个模块独立语法检查通过

## 4. 目标架构

```
game.js (重构后 ≈ 2000-3000 行)
├── 入口 + 全局状态初始化
├── UI 层 (render/close/open 系列函数)
└── 跨 Context 编排

domains/
├── cultivation/
│   ├── entities/       (Player.js, Realm.js)
│   ├── services/       (CultivationService.js)
│   └── values/         (RealmLevel.js, TribulationResult.js)
├── pet/
│   ├── entities/       (Pet.js, Gene.js)
│   ├── services/       (PetService.js)
│   └── values/         (PetGene.js, AwakeningSkill.js)
├── combat/
│   ├── entities/       (CombatState.js, Action.js)
│   └── services/       (CombatService.js)
├── ranking/
│   ├── entities/       (RankInfo.js, Season.js)
│   └── services/       (RankingService.js)
├── achievement/
│   ├── entities/       (Achievement.js, Title.js)
│   └── services/       (AchievementService.js)
├── inventory/
│   ├── entities/       (Item.js, Equipment.js)
│   └── services/       (InventoryService.js)
└── shared/
    ├── constants/      (CONFIG, REAMS, etc as value objects)
    └── utils/          (helpers used across contexts)

build_vite.js          (拼接所有模块 + node --check)
```

## 5. 重构顺序（增量）

**Phase 1: 提取常量与值对象**
- 提取 CONFIG, REALMS, SEASONS, ACHIEVEMENTS 等为 `domains/shared/constants/`
- 提取 `gameState` 类型定义为 `domains/shared/`

**Phase 2: 提取 Inventory + Achievement**
- 最小耦合，易独立验证
- 产出: `domains/inventory/`, `domains/achievement/`

**Phase 3: 提取 Cultivation + Pet**
- 核心玩法域
- 产出: `domains/cultivation/`, `domains/pet/`

**Phase 4: 提取 Combat + Ranking**
- 战斗与天梯
- 产出: `domains/combat/`, `domains/ranking/`

**Phase 5: 重构 UI 层 + 入口**
- render/close/open 函数按 Context 对齐
- game.js 精简为编排层

## 6. 验收标准

1. game.js 行数降至 3000 行以下
2. `node --check domains/**/*.js` 全部通过
3. `npm run build` 产出 dist/game.js 与重构前功能等价
4. 核心玩法（修炼→突破→天劫）流程可正常运行
5. 每个 phase 结束游戏可玩（不破坏功能）
6. CI 有模块级语法验证

## 7. 约束

- 不改变游戏功能逻辑
- 不改变 UI/UX
- 保留现有 `gameState` 数据结构兼容性（save/load）
- 重构期间不添加新功能
- 部署方式不变（GitHub Pages）
